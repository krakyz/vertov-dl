# Архитектура vertov-dl 0.1.0-alpha.1

WebUI TypeScript/Vite/CSS без React → FastAPI → SQLite + один Manager → изолированные дочерние процессы yt-dlp/FFmpeg. Готовые файлы передаются FileResponse/Range, не прямыми CDN-ссылками.

- До двух probe-процессов одновременно с одним download/convert. Несколько uvicorn workers/реплик на одном volume не поддерживаются.
- Probe выдаёт безопасное событие metadata до скачивания необязательного превью. Оно позже распространяется связанным задачам.
- MetadataCache: успехи 300 секунд в памяти; generation cookies и ticket запроса защищают от устаревших ответов. force/retry обходят кэш.
- Download заново получает потоки через yt-dlp; совместимые части продолжаются. Смена selection удаляет старые media.*. Отмена удаляет каталог; ошибка сохраняет его до удаления/квоты/TTL.
- Конвертация MP3 использует только FFmpeg и закреплённый hardlink исходного файла. yt-dlp не запускается.
- Фоновый ffprobe обогащает ready-файлы: кодеки, width/height, FPS. Ошибка проверки не меняет completed и не задерживает передачу браузеру.
- Library управляет готовыми файлами: 10 ГиБ/30 дней. TemporaryFiles управляет частями: 10 ГиБ/7 дней. Активные HTTP-выдачи удерживают файл от удаления.
- Заголовки остаются оригинальными в UI, download_filename нормализует только браузерное имя. Серверные имена и докачка от заголовка не зависят.
- CookieVault: AES-GCM, plaintext только в памяти; обязательный SOCKS gateway, запрет LAN/private целей, локальные FFmpeg wrappers.

Схема таблиц создаётся metadata.create_all. До изменения таблиц нужен Alembic baseline. Технические имена media_loader, MEDIA_*, cookie-контекст и browser storage keys сохраняются для совместимости.

История решений: docs/adr/0001…0007. Исторические ADR описывают решения на соответствующий момент; актуальное состояние — этот документ и README.
