# ADR-0006: Быстрые метаданные без ожидания скачиваний и превью

Статус: реализовано, 2026-11-02.

Один экземпляр Manager остаётся владельцем SQLite-очереди. Он запускает до двух probe-процессов и одну задачу скачивания/конвертации одновременно. Активные ID учитываются до фактического завершения дочерних процессов; остановка приложения отменяет все процессы. Несколько workers/реплик не поддерживаются.

Worker probe отправляет безопасное событие metadata с названием и форматами сразу после extract_info. Manager завершает пользовательскую задачу до получения превью; его необязательная загрузка продолжается в том же дочернем процессе и занимает probe-слот. Ошибка/остановка этого этапа не отменяет успешные метаданные. Полученное превью распространяется на связанные копии probe и задачи скачивания без изменения TTL. Download заново получает актуальные потоки, но не делает отдельный сетевой запрос превью.

Кэш хранится только в памяти процесса на 300 секунд, содержит ссылки на успешные probe-записи, не сохраняет URL потоков или ошибки. Ключ — проверенная исходная ссылка (WebUI нормализует YouTube). force и retry обходят кэш. Успешный импорт/удаление cookies инвалидирует кэш и поколения выполняющихся запросов. Ticket нового запроса запрещает позднему ответу старого запроса заменить свежий кэш. После перезапуска кэш пустой. Записи и ticket-индексы ограничены по количеству.

Сведения о длительности очереди, extract_info и превью записываются числовыми полями queue_seconds, extraction_seconds и thumbnail_seconds без сырых сетевых логов. TTL/повторы сети не сокращены.
