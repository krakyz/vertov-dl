# Установка и обслуживание vertov-dl

## Требования

Linux Docker Engine + Compose v2, SOCKS5 на хосте и достаточно свободного диска. Текущий compose использует host network и слушает только 127.0.0.1:47831. Для доступа используйте SSH-туннель; не открывайте порт в интернет. Новый volume инициализируется владельцем 10001:10001.

## Первая установка

```bash
python3 scripts/generate-token.py
docker compose config --quiet
docker compose build --pull
docker compose up -d
docker compose ps
```

Скрипт создания ключа не перезаписывает существующий файл. На Linux каталог секретов 0700, файл 0444 для чтения контейнером. Смотрите ключ только локально. Для прокси на другом адресе измените MEDIA_PROXY_URL; не отключайте TLS/проверку целей.

## Резервная копия

Остановите приложение для согласованной копии SQLite и файлов:

```bash
docker compose stop
docker compose run --rm --no-deps --user 0 --entrypoint tar app -C /data -czf - . > vertov-dl-data-backup.tar.gz
```

Отдельно сохраните `deploy/secrets/media_auth_token.txt` и compose с настройками. Архив /data содержит приватные ссылки, медиа и зашифрованные cookies; не помещайте его в Git. Для расшифровки cookies нужен прежний ключ доступа.

## Обновление

Запомните предыдущий тег/ID образа и сохраните резервную копию. Сохраните имя Compose-проекта и volume: смена project name создаст другой volume, а не перенесёт данные.

```bash
docker compose stop
docker compose build --pull
docker compose up -d
docker compose ps
```

Не используйте `down -v`: это удаляет данные. Не заменяйте ключ. При обновлении старой тестовой установки сохраняйте её project name через `docker compose -p PREVIOUS_PROJECT ...` либо явно подключите прежний volume; сначала проверьте `docker compose config`.

## Откат

Остановите приложение, укажите прежний образ и запускайте с `--no-build`. Если схема данных изменилась — сначала восстановите копию /data, снятую перед обновлением. Для alpha.1 таблицы SQLite не менялись; новые служебные поля хранятся в JSON details. Перед первым изменением таблиц обязательны миграции.

## Параметры хранения

MEDIA_LIBRARY_MAX_BYTES=10737418240, MEDIA_RETENTION_HOURS=720; MEDIA_TEMPORARY_MAX_BYTES=10737418240, MEDIA_TEMPORARY_RETENTION_HOURS=168. Старые ошибочные части вытесняются первыми, активные задачи не удаляются. Проверка раз в 5 секунд, жёсткую квоту файловой системы это не заменяет.

При остановке активные процессы завершаются; queued сохраняются. Прерванный download становится failed и может продолжиться с тем же каталогом. Отмена пользователем очищает части. Совместимость формата проверяется перед использованием старых частей.

Native-обновления требуют нового образа: копирование Python-исходников/source-overlay не меняет FFmpeg/libavcodec. Сборка проверяет минимальную исправленную версию по CVE-2026-8461; после сборки запустите python scripts/check-image.py vertov-dl:0.1.0-alpha.1. Проверка относится к этой CVE и не заменяет регулярное обновление/аудит зависимостей.
